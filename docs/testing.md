# Testing

## Layers

| Layer | Tooling | What's covered |
|---|---|---|
| Unit | JUnit 5 | `Money` math, invariant validation, ECB XML parsing, conversion rounding |
| Integration | Testcontainers (Postgres 16, Redpanda) | everything below |
| API | MockMvc + JWT | auth, RBAC, validation shapes, idempotency headers, error codes |
| Concurrency | thread pools | 400 parallel transfers: global `debits == credits`, per-account cache == postings |
| Idempotency | — | replay, key-reuse rejection, 8-way racing duplicates, failure replay |
| Outbox | raw Kafka consumer | relay publishes staged events; poison path quarantines |
| Projection | — | event → read model; destroy + rebuild from postings; tamper detection |
| Webhooks | — | bad signatures rejected pre-DB; duplicate callbacks no-op |
| Reconciliation | — | missing/amount/late settlements detected; reruns don't duplicate |
| Load | k6 | soak, hot-account contention, idempotency replay (see below) |

## Running

```bash
mvn verify            # unit + integration (needs Docker for Testcontainers)
mvn -DskipTests package
```

## Load tests (k6)

```bash
k6 run load-tests/k6/transfer-soak.js
k6 run load-tests/k6/transfer-hot-account.js
k6 run load-tests/k6/idempotency-replay.js
```

- `transfer-soak`: steady-state throughput; asserts p95/p99 budgets.
- `transfer-hot-account`: all VUs drain one account; teardown **fails the run**
  if the cached balance diverges from postings.
- `idempotency-replay`: 50 attempts, one key; teardown fails unless exactly
  one transfer landed.

Results land in `load-tests/k6/results/` — generated by execution, never
hand-written (see docs/performance.md).

## Invariants asserted everywhere

1. Per transaction: `sum(debits) == sum(credits)` per currency.
2. Globally: net across all postings is zero per currency.
3. Per account: cached balance == postings-derived balance.
4. Conservation: total money across accounts never changes except via
   explicit, audited operations.
